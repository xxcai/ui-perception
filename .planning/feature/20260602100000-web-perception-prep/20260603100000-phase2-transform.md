# Phase 2: Web Transform + 格式统一

## 状态

进行中

## 背景

Phase 1 已完成：Web capture 链路跑通，JS 注入 ARIA tree → JSON 返回正确。
Phase 2 目标：实现 transform（JSON → YAML），同时统一 native/web 输出格式。

## 设计决策

### 1. 共享类型下沉 perception-core

Native/Web transform 共用的语义模型从 native-plugin 下沉到 perception-core，消除 web-plugin 对 native-plugin 的依赖。

| 旧名（native-plugin） | 新名（perception-core） |
|---|---|
| NativeSemanticNode | SemanticNode |
| NativeSemanticRole | SemanticRole |
| NativeBounds | Bounds |
| NativeRoleDecision | RoleDecision |
| NativeSnapshotRenderer | SnapshotRenderer |
| NativeSnapshotRenderOptions | SnapshotRenderOptions |
| NativeRefAssigner | RefAssigner（prefix 参数化） |
| NativeSemanticStates | SemanticStates |

### 2. States 格式统一

统一为 key=value 格式（对齐 web，模型基于 web 训练数据更多）。

| 旧格式 | 新格式 | 说明 |
|---|---|---|
| `clickable` | `clickable` | 不变 |
| `clickable-inferred` | `clickable=inferred` | key=value |
| `clickable-guessed` | `clickable=guessed` | key=value，不再 alias 成 inferred |
| Native input text → name | text → `value=xxx` state | 对齐 web |

重叠 states（已一致，无需改）：`disabled`、`checked`、`focused`
Native 独有 states（暂不动）：`scrollable`、`password`、`selected`、`needs_visual_desc`
Web 独有 states：`level=N`、`indeterminate`、`pressed`、`pressed=mixed`

### 3. Native input hint/value 改造

当前 native 的 input（EditText）text 直接当 name。改为：
- name 取 hint（> contentDescription > resourceId）
- text 放入 `value=xxx` state

需要改动：
- ViewHierarchyDumper 新增 hint 提取
- NativeViewNode 新增 `hint` 字段
- NativeRoleResolver / NativeSemanticTreeBuilder 对 INPUT 角色调整 name 来源

### 4. Web transform 链路

```
JSON (JS capture 输出)
  → WebJsonParser.parse()        [JSON → SemanticNode 树]
  → TreeNormalizer.normalize()   [generic 折叠 + 冗余文本去除]
  → RefAssigner.assign(root, "w") [分配 w1/w2/...]
  → SnapshotRenderer.render()     [SemanticNode → YAML]
```

#### 4a. Generic 折叠（参考 Playwright normalizeGenericRoles）

无名称的 generic 节点，如果只包了一个子节点，移除该 wrapper。
例如 `<div><button>Submit</button></div>` → 直接输出 button，不输出外层 generic。

#### 4b. 冗余文本去除（参考 Playwright normalizeStringChildren）

如果节点的唯一子节点是 text，且文本内容与 name 完全相同，跳过该子节点。
例如 `button "Click Me"` 的子文本 `"Click Me"` 被移除，避免 `button "Click Me": "Click Me"`。

#### 4c. 不做的事

- 不做 Playwright 的模糊冗余检测（textContributesInfo，基于最长公共子串）
- 不做增量 diff
- 不做 Playwright 的 inline generic 折叠（已在 JS textFromContent 中处理）

### 5. Ref 分配差异

Native 和 Web 的 ref 分配逻辑基本相同，只有两个差异：
- 前缀不同：native=`n`，web=`w`
- Web 没有 clickable-inferred/clickable-guessed（只有 clickable），LIST_ITEM 处理更简单

统一为 RefAssigner + prefix 参数，无需分两个实现。

## 步骤

### 阶段一：基础设施

1. 共享类型下沉 perception-core（SemanticNode / SemanticRole / Bounds / RoleDecision / SnapshotRenderer / SnapshotRenderOptions / RefAssigner / SemanticStates）
2. States 格式更新（clickable=inferred/guessed，移除 guessed→inferred aliasing）
3. 编译通过 + native 测试通过

### 阶段二：Native input 改造

4. ViewHierarchyDumper 新增 hint 提取
5. NativeViewNode 新增 hint 字段
6. INPUT 角色调整 name 来源（hint > contentDescription > resourceId），text → value=xxx state
7. native 测试通过

### 阶段三：Web transform

8. 新建 WebJsonParser（JSON → SemanticNode）
9. 新建 TreeNormalizer（generic 折叠 + 冗余文本去除）
10. WebPerceptionPlugin.transform() 接入
11. 端到端验证（web baseline 页 → YAML 输出）

### 阶段四：验证

12. Native 页面回归测试（格式变更后功能不变）
13. Web 页面端到端验证
