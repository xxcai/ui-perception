# UI Perception

UI Perception 是一个 Android 端 UI 感知研究项目，目标是探索如何将手机屏幕上的 UI 信息转换成更适合大模型理解的数据表示，并建立可持续迭代的测评基线。

本项目只关注 UI 感知数据的生成、处理和评测，不包含 Agent 决策、规划或执行操作。

## 研究目标

1. 研究如何让大模型更快捷、准确地识别当前手机屏幕内容，为后续推理系统提供可靠上下文。
2. 建立测试基线，用数据支撑后续方案迭代和效果对比。

## 项目边界

本项目关注：

- 当前页面内容采集
- 多来源 UI 数据处理
- 面向大模型的数据表达
- 感知结果与基准意图的评测

本项目不关注：

- Agent 操作执行
- 自动点击、滑动、输入
- 任务规划与工具调用
- 多轮交互决策

## 整体流程

项目流程分为四个阶段。

### Phase 1：页面准备

准备用于测试和对比的标准页面与基准数据。

- 基准原生页面
- 基准 Web 页面
- 人为意图配置

### Phase 2：页面抓取

从不同通道采集当前页面信息。

- 原生 XML
- Web DOM
- 截图 + OCR
- 截图 + 小模型

### Phase 3：数据处理

对不同来源的数据进行裁剪、清洗和融合，输出适合大模型消费的结构化结果。

- 各抓取方式独立裁剪
- 多源数据相互补充
- 去除冗余和噪声
- 保留关键 UI 语义

### Phase 4：效果测评

将处理结果与基准意图进行对比，衡量 UI 感知质量。

- 处理结果 vs 基准意图
- 准确率
- 召回率
- 其他任务相关指标

## 架构原则

### 可插拔

各阶段组件采用可插拔设计。页面来源、抓取方式、处理策略和评测指标都应能独立替换。

实现上优先使用简单 DI 思路，例如通过接口、构造函数注入或注册表组合组件。

### 够用优先

本项目是研究工程，不追求提前抽象完整平台能力。

原则：

- 当前阶段只抽象已经出现的变化点
- 优先保证实验链路清晰可跑
- 避免复杂框架和过早分层
- 新增组件必须服务于可验证的实验目标

## 开发方式

项目采用渐进式开发。

第一阶段先搭建清晰、可运行、可扩展的框架，把核心流程、接口边界和最小数据链路建立起来。后续开发者可以按照已有接口和目录结构，通过“填空”的方式补充具体能力，例如新增页面样例、抓取通道、裁剪策略、融合逻辑或评测指标。

开发时优先遵循以下规则：

- 先定义当前能力在流程中的位置，再实现具体逻辑。
- 新能力应尽量挂接到已有接口或注册点。
- 不为了未来可能出现的需求提前设计复杂抽象。
- 每次补充能力都应给出可验证的输入、输出和评测方式。
- 保持主流程可运行，即使某些能力仍是占位实现。
